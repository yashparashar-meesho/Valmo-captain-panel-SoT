Never do this

Every line here cost someone real time at least once. Each says what not to do and what actually happens if you do it, because a rule without a consequence gets ignored.

Editing the wrong file

neverbecause
Edit assets/kit.cssIt is generated. The next export silently overwrites your change and you lose it without an error. Edit the <style> block in source/flow-ledger.html.
Edit index.html, screens/*.html, components/*.htmlAll generated by scripts/export_to_github.py. Same silent overwrite. The source is source/flow-ledger.html + source/data-seed.json.
Edit docs/pages.md or docs/components.mdGenerated by scripts/build_docs.py from the catalogue.
Write source/data-seed.json without updating the copy embedded in flow-ledger.htmlThey must be written together. When they drifted once, three icons silently reverted and nobody noticed until the pages were opened. check_v2_sync.py now fails on it.

Markup and CSS

neverbecause
Put a <script> inside a screen's codeThe literal </script> closes the seed element early. The JSON then fails to parse with an error that points nowhere near the cause. Vendor the behaviour under source/assets/vendor/ and let VENDOR_RULES pull it in.
Add font-weight: 500Mier B02 has no 500 face. It silently resolves to 400 Book — measured identical, to the hundredth of a pixel. You have written a rule that does nothing while believing you changed something.
Use line-height: normalIt depends on the font file. If Mier ever falls back to the metric-matched stand-in, every control using it changes height. Always set an explicit line-height.
Use overflow: auto for a scroll areaThe scrollbar appears and disappears, shifting layout by its own width, and users cannot tell the area scrolls. Use scroll, per layout-rules.md.
Give a component its own copy of the kitThat duplication was once 62% of the file. The kit lives once.
Add a third section to a pageNo screen has three. See section-rules.md — it is almost always two pages or a misread card.

Measuring against live

neverbecause
Read sizes, borders or fills off a screenshotAt the scale the tools return, a 1px #E6EBF2 border is invisible and #F2F5FA on white is a 4% step. One outlined card holding two rows read as two grey tiles. Screenshots tell you something is wrong, never what it should be.
Match an element by text without scoping past the railThe rail repeats module names. leaf('Pilot Rate Card') matched the nav item, not the card header, and shipped the wrong type size. Filter on getBoundingClientRect().left > 250 and assert exactly one match.
Assume a control is the same everywhereCheck a second module before changing a shared component. The language button is on DC Capacity and eight times on Growth Dashboard.
Round live to the nearest token without saying soFine to deviate — four DC Capacity values deliberately do. Not fine to deviate quietly. Write it in a comment and in fidelity-checklist.md, or the next person "fixes" it.

On the live panel

neverbecause
Click Save Delivery & Pickup CapacityWrites real capacity for a real DC. Read-only measurement always; type into fields to see states, never submit.
Click View Details on Growth DashboardExplicitly out of scope — that page is not being rebuilt.
Click Download AWB DetailsUI only.

When in doubt on live: reading the DOM and typing into inputs is safe. Anything that submits is not.

Git and process

neverbecause
git commit --no-verifySkips TruffleHog. The repo is public — a leaked key is public immediately.
git add -A without checking.claude/ and scripts/collect_elements.py are untracked on purpose and are not in .gitignore.
Ship a module in the same PR as its new componentsComponents first, separately. A module PR that depends on components not yet upstream cannot be reviewed on its own.
Push explorations to mainLosing wireframes go to the Idea Wall or a branch that is never merged. The catalogue is the source of truth; the wall is a photo of an idea.
Let Figma become the sourceFigma is the gallery. Screenshots cannot be diffed, measured or promoted from. HTML stays the artifact.

Running the method

Each of these happened on the first real run of the slipstream skill.

neverbecause
Build a design whose blocks differ from the schematic that wonThe schematic is a contract. If a reviewer cannot tell which wireframe became the design, the comparison was decoration and the choice they made was not the choice they got. New blocks are a change to surface, not to add quietly.
Draw tabs as a row of equal bordered boxesThat reads as a button group and shows nothing about which view is active. Tabs are a row with the active one underlined — wfc-tabs. wfc-steps is for a progression, never navigation.
Carry on after an answer without updating the brief and the DRDAn answer given in chat is not a decision until it is written down. Later steps check against the brief, so a stale brief validates work against a document everyone has stopped believing — and the reasoning is gone once the chat is.
Let an answer quietly shrink or grow the approach set"Ignore AMs" removed a whole approach in the capacity-cut run, because that approach existed to be read by two people. Say so. A silently shrinking option set reads as carelessness; an explained one is the method working.
Renumber constraints or tests after the brief is approvedOther documents reference C4 and T2 by name. Renumbering silently repoints every reference, and no check would catch it. Mark withdrawn items withdrawn; give new facts new numbers.
Skip the comparison sheet because the DRD already named a favouriteLiking an approach in the DRD is liking a paragraph. Shapes argued as sentences lose to shapes seen side by side — that is why Section 1 says not to converge. The preference is provisional until it has been looked at. The user may say "skip it"; it is never yours to decide for them by reading ahead.
Decide where it lives before the approaches existPlacement is one of the things the five approaches differ on. Settle it first and the DRD diverges inside a box nobody argued for. It goes in the DRD, and the question goes in its open questions.
Skip the DRD because Section 1 "does not block"Not blocking means do not wait for sign-off. The artefact is still required. Skipped once already, and the chosen approach was then compared against nothing on paper — including the option that had been missed. Section 2 does not start until DRD.md exists.
Propose a new surface before asking whether a control would doA date dropdown, a filter or a toggle on what is already there often does the whole job. "Show me last week" is a date control, not a screen. A tab proposed where a filter would have done is work nobody needed, in a place nobody will look.
Recommend a nested page without naming what it costsDepth costs visibility. 1c is seen by whoever goes looking for it. Say so in the same breath — "it fits here, but it will be seen less".
Rule a placement out because of low visibilityThat is a cost to state, never grounds to remove an option — not even when the problem itself is one of awareness. If it is the best fit and everyone agrees the visibility is enough, it ships. Put the trade in front of the person deciding; do not decide by quietly dropping a choice.
Proceed carefully from a problem you have not understoodEverything downstream inherits the misreading: a correct-looking DRD, five careful approaches, a finished design that solves the wrong thing. No later stage catches it. If the KRD is thin, go back to it.
Build the same thing in two modulesTwo homes means two things to maintain and, soon, two versions of the truth. One module is the home; the others get a door — an entry point or a line that links to it.
Reach for a new module because two modules both seem to own the subjectShared ownership is a sign the subject has not been named sharply enough, not that it needs its own rail slot. Pick the better home, put a door in the other.
Offer only "extend this page" or "a new page"There are four shapes of change, and the third — a new screen inside an existing module, i.e. a tab — is the one that gets missed. tabs already exists and two modules use it.
Read a screen's notHere as the module'sanswers and notHere are scoped to one screen. A second screen in the same module is not covered by them. This is what made a tab invisible as an option.
Judge what is possible by the target module's current shapeA module having no tabs today is not evidence against a tab — any module can take one. Which modules happen to use a pattern now says nothing about which may. Judge by whether the thing fits the page, never by the page's current furniture.
Give out a URL before the server is actually serving itA link was handed over for a server that never started, because the port was in use. Check the port is free and the page returns 200 before sending the link.
Hand over the DRD as a raw .mdThat is the source of a document, not the document. It reads badly and approving it feels like reviewing a diff. Render it: python3 scripts/render_doc.py DRD.md.
Build anything before the DRD is approvedThe gate is blocking. Not "shared", not "sent" — approved in words. Fetch nothing until then either.
Invent approaches and then check them against the axesBy the third one you have anchored on whatever came to mind first, and the check only confirms it. Build the candidate set from the brief's own lists — the modules it named, the actors it extracted, the moments in its situations — then prune. Selecting beats imagining.
Let a module named in the brief vanish from the approachesEvery module in what it touches appears in the approach table or is ruled out in a sentence. Growth Dashboard was named in the capacity-cut brief and then simply absent — not rejected, absent — and only a human reading the table caught it.
Stop varying placement because it is "not the design axis"Placement is one axis, not the excluded one. Saying it was not the design axis made the next run drop placement variation entirely, and a whole module went with it. Vary placement and the rest.
Produce five approaches that differ only on placementPlacement is the entry axis, not the design axis. Five points on one axis is one idea explored five times. Place each approach on the axes — what is shown · who acts · when it is surfaced · how it is framed · depth — and the thinness shows itself.
Pad to five when the problem has twoThe count follows the problem. Three real ideas and two costumes waste attention exactly where it is needed most. Say two, and say why only two.
Report a clustered set as if it were five choicesIf three are the same idea in different clothes, name the real fork underneath and ask which side to explore. That is worth more than five options.
Design only the happy path the KRD describedA KRD describes the happy path almost every time. Run the sweep — data · time · permission · lifecycle — and the cases it never mentioned fall out mechanically. Each becomes a constraint or a test, and each has to appear as a situation in the shapes.
Ask a design question as though it were a gap in the KRDA KRD question is about what the KRD does not say. A design question is yours to decide and state. Mixing them makes the reader adjudicate your choices as facts — a third of the demo's "six gaps" were this.
Write an approach you would not defendEvery entry gets Why it can work argued as though it were the one being built. An approach present only as a trade-off line is a straw man, and five straw men are not a choice — they are the recommendation with scenery around it. The reader has to be able to disagree with you from the page.
Put a comparison sheet's layout rules on the sheetThe pill strip of max 2 sections · 250px rail · tokens only is for the person building, not the person choosing. It sits at the top of the page where the argument should start, and it was cut for exactly that reason. The rules live in layout-rules.md.
Describe an approach without the captain's journeyA shape reads as plausible for exactly as long as nobody walks through it. The numbered steps are what expose a shape that cannot finish: B in the capacity-cut run ended at "They stop there", and that line ruled it out faster than its test coverage did. The journey goes in the DRD entry and beside the schematic, word for word.
Draw the schematic rail as anonymous bars, or light the same one on every cardPlacement is the axis these cards exist to compare. A rail that does not name the module, or names it the same on all five, is a placement comparison that says nothing about placement — and it shipped that way in the worked example until a real run caught it.
Write a sentence that has to be read twiceIt fails quietly, and the reader blames themselves. One idea per sentence; a dash holding two clauses is usually two sentences not yet separated. See Plain English, or it does not get read in design-method.md.
Name an ID before saying the thing"C4's trap" makes the reader stop and fetch C4 before they can read the clause it sits in. Say the thing, then name the ID — "a new FE has to be hired (C4)". Same for a legend: "green means it can show this", never "a filled chip indicates coverage".
Build a wireframe that looks finishedReal components and real colour turn review into proofreading instead of choosing. Grey only: kit.css + wireframe.css, .wf-box with a label saying what information goes there. Colour returns at promotion.
Build a greyed full-size wireframe of a chosen shapeThere is no stage between picking an approach and building it. Once the shape is decided, the next useful artefact is the design — a full-size wireframe of work already understood is a drawing of a decision.
Hand over several links for several promoted designsComparing two designs means flicking between them in the same spot. Two tabs lose the alignment and most of the comparison with it. One page, a small V1 / V2 switcher above the panel.
Fetch screens, icons or fonts during Section 0Section 0 is reading and discussion. Those files may belong to a screen that is about to be ruled out. One batched fetch, after the DRD is approved.

Working style

neverbecause
Re-upload or re-publish while still iteratingEvery approval prompt spends the user's attention. Verify locally first, publish once.
Report a step as done without running itA script that logged six successful edits had written nothing — a later assertion threw before the file was saved. Persist after each step, and verify the artefact, not the log.
Invent a count ("5 approaches", "3 options")Fixed counts manufacture filler. Say how many are genuinely distinct, even when that is two.
